# ASD-STE100 Writing & Audit Reference

<!-- Reference standard based on ASD-STE100 (Simplified Technical English) for AI-generated artifacts. -->

## 1. Core Purpose
The ASD-STE100 standard minimizes conversational padding, vague phrasing, and cognitive fatigue. Human auditors can rapidly review and verify agent outputs.

---

## 2. Nine Essential Rules for Agents

### Rule 1: Word Count Limits
- **Procedural instructions / steps:** Maximum **20 words** per sentence.
- **Descriptive / contextual statements:** Maximum **25 words** per sentence.
- If a sentence exceeds the limit, split it into two atomic sentences.

### Rule 2: Active Voice & Imperative Mood
- Use active voice: `"The agent generates the schema"` (not `"The schema is generated by the agent"`).
- For procedural steps, use the imperative command form: `"Open the console"`, `"Deploy the function"`, `"Assert the status"`.

### Rule 3: Single Meaning per Word
- Choose one standard word for each concept. Do not alternate synonyms.
- Use `"start"`, not `"launch"`, `"initiate"`, or `"commence"`.
- Use `"stop"`, not `"terminate"`, `"halt"`, or `"kill"`.
- Use `"verify"`, not `"ensure"`, `"check on"`, or `"validate"`.

### Rule 4: Ban Conversational Fluff & Hedging
- Eliminate preambles: `"It is important to note that..."`, `"Please be aware that..."`.
- Eliminate hedges: `"This might potentially improve..."`, `"It could perhaps be useful to..."`.
- State facts directly: `"This setting reduces latency"`.

### Rule 5: One Instruction per Sentence
- Prohibited: `"Click the submit button and check that the notification shows success and refresh the table."`
- Approved:
  1. Click the **Submit** button.
  2. Verify that the notification displays `"Success"`.
  3. Refresh the table.

### Rule 6: No Noun Clusters
- Do not chain more than three nouns together.
- Prohibited: `"Enterprise resource planning system user credential access token verification failure"`
- Approved: `"Failure to verify user credentials in the ERP system"`

### Rule 7: Avoid Gerunds and Hidden Actions
- Replace gerunds (`-ing` forms) with direct verbs or nouns.
- Prohibited: `"For handling connecting to Firebase..."`
- Approved: `"To connect to Firebase..."`

### Rule 8: Restrict Negative Statements
- Use positive statements whenever possible.
- Prohibited: `"Do not fail to verify the certificate."`
- Approved: `"Verify the certificate."`

### Rule 9: Priority of Tables and Diagrams
- Follow Andrej Karpathy's output hierarchy:
  1. Use Mermaid diagrams for state transitions, sequences, and workflows.
  2. Use Markdown tables for multi-variable properties, comparisons, and checklists.
  3. Use ASD-STE100 prose only for narrative context that cannot be structured visually.

---

## 3. Compliance Scoring Metric (80% Target)
The Project Documentation Agent audits text with the following formula:

$$\text{Compliance Score} = 1.0 - \left(\frac{\text{Violations}}{\text{Total Sentences}} \times 0.5\right)$$

- Document passes review when score $\ge 0.80$.
- Sentences exceeding 25 words automatically trigger a violation flag.
